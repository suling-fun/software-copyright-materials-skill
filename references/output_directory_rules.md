# 输出目录与材料归档规范

本规范适用于软著材料生成、截图整理、版权中心填报和签章交接的全部阶段。在创建或写入任何文件前，须先确定目标项目根目录，并以该目录为基准解析以下相对路径。

## 固定根目录

正式执行时，所有材料与中间产物统一写入：

```text
<项目根目录>/软件著作权申请资料/
```

「项目根目录」指当前申请对应软件项目的根目录，不是 Skill 目录、用户主目录或任意终端当前目录。使用脚本的相对默认路径前，须先进入目标项目根目录；也可以显式传入该根目录下的完整输出路径。

只有测试 Skill 自身时，才允许通过命令参数把输出显式指向 `/tmp`、`/private/tmp` 或其他隔离的临时目录。测试产物不得混入任何真实项目的申请资料。

目录按实际需要创建，不要求在流程开始时生成全部空目录。

## 归类规则

- `analysis/` 只保存项目扫描和结构化分析结果，不放业务成稿、申请材料或浏览器记录。
- `草稿/` 保存所有尚需模型研判、用户补全或确认的内容，包括业务理解、申请信息、代码抽取草稿和操作手册草稿。
- `操作视频/` 只保存视频抽帧产物和帧清单。外部原始视频保留在原位置，在 `视频证据.md/json` 中记录来源路径，不强制复制大文件。
- `用户截图/` 保存用户提供的原始图片，尽量保持原文件不变；`截图/` 保存从视频、浏览器或用户截图中筛选、裁定并按手册模块整理后的图片。版权中心页面状态截图不属于操作手册截图，应放入 `提交记录/`。
- `正式资料/` 是正式可交付或可上传材料的唯一目录。Word、TXT、最终 PDF 及对应生成报告在此归档；草稿、门禁、浏览器状态证据、签章页和回执不得混入。
- `提交记录/` 保存版权中心填报过程记录、流水号、平台状态证据、平台生成的待签署签章页、完成签署或盖章后的扫描件，以及回执。签章页和回执属于特定申请实例，不放入 `正式资料/`。
- 根目录只保存环境检查、根级阶段确认/门禁文件和总校验报告。业务阶段自身的确认状态随对应草稿 JSON 保存在 `草稿/`。

## 命名规则

- 正式材料的文件名以用户已确认的「软件全称」和「版本号」为准，沿用生成脚本定义的名称；不得用临时简称覆盖已确认字段。
- 代码和操作手册 PDF 应与对应 DOCX 使用相同主体名称，仅扩展名不同。平台上传后仍以本地正式文件名记录，不另造难以回溯的别名。
- 操作手册截图按功能模块和页面含义命名，例如 `项目管理-列表页.png`；用户原始截图不因整理而覆盖，可复制到 `截图/` 后另行命名。
- 视频帧沿用脚本生成的 `frame_0001.png` 递增格式，不按主观功能重命名原始帧。
- 提交过程文件必须带当前申请的流水号；流水号尚未生成时可暂用 `待分配`，取得后在操作记录中建立明确对应关系。状态证据使用 `YYYYMMDD-HHMM-平台状态-状态证据.<扩展名>`。
- `版权中心操作记录.md` 采用单项目持续追加方式，逐次记录时间、已验证状态、所用正式材料绝对路径、当前页面和下一步；不得为同一项目反复创建含义相同的多个交接文档。

## 禁止事项

- 不得把正式运行产物默认写到临时目录，也不得把 Skill 测试产物写入真实申请目录。
- 不得把草稿、分析文件、原始视频、浏览器状态截图、签章页或回执放入 `正式资料/`。
- 不得直接编辑或覆盖 `用户截图/` 中的原始图片；整理结果另存到 `截图/`。
- 不得复制外部原始视频作为默认动作；只有用户明确要求归档副本时才复制。
- 不得在不同软件或不同流水号之间复用签章页、回执、状态截图和操作记录。
- 不得因为采用新规范而自动移动、删除或重命名既有申请材料。

## 旧项目兼容原则

已有项目可能把文件放在根目录、使用 `操作视频2/` 等历史目录，或已有单独的交接文档。遇到这些情况：

1. 保留原文件和原路径，不自动整理、迁移、删除或覆盖。
2. 读取旧文件时允许使用其现有路径；自本次继续产生的新文件开始遵守本规范。
3. 若旧路径仍被当前门禁或脚本引用，优先保持兼容，不得为目录整洁而破坏可继续执行性。
4. 在 `提交记录/版权中心操作记录.md` 或最终交接中注明仍在使用的历史路径，避免后续人员误认。
5. 只有用户明确要求迁移并确认目标范围时，才另行执行迁移；迁移前后都要核对文件清单和内容。

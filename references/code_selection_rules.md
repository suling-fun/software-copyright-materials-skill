# 代码抽取规则

## 选择方式

脚本只生成候选源码清单，不默认决定抽取文件。模型需要先理解项目业务、页面入口和源码职责，再决定抽取哪些文件，并在 `代码文件选择.json` 中填写：

- `selected`
- `model_reason`

代码材料抽取必须保证代码和功能方法的完整性：按完整文件抽取（自动去除纯空行），不按任意行区间截取，避免把函数或方法从中间截断。

选择时优先考虑能让审核员看懂软件真实功能和运行逻辑的源码，通常按以下优先级判断：

1. 前端入口、路由、页面、核心组件、接口封装、状态管理、工具函数。
2. 如果前端相关代码不足 60 页，再补充后端服务、业务处理等相关源码。

具体选择由模型根据项目实际判断，不能用固定路径规则直接拍板；不要默认抽取全量代码库，补充文件同样要写入 `代码文件选择.json` 并由用户确认。

## 排除项

排除以下内容：

- `node_modules`
- `dist`、`build`、`.next`、`.nuxt`、`coverage`
- lock 文件
- 图片、字体、二进制文件
- sourcemap、minified 文件
- 自动生成文件
- 过短且无业务意义的配置文件

## 真实性要求

- 保留原始代码文本。
- 可添加文件路径标记用于追溯。
- 不改写业务逻辑。
- 不使用 AI 补齐代码。

## 用户确认要求

- 代码抽取前必须先生成 `代码文件候选清单.md` 和 `代码文件选择.json`。
- 模型必须先填写抽取选择和 `model_reason`，再让用户确认或手动调整 `selected`。
- 抽取脚本必须以 `代码文件选择.json` 为准，不能绕过确认步骤直接抽全量代码库。
- `代码提取清单.md` 必须记录每个文件的抽取行段，便于回溯。
